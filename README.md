# VIN Decoder

SPA для розшифровки VIN-кодів автомобілів через відкрите API [NHTSA vPIC](https://vpic.nhtsa.dot.gov/api/).

React 19 · Vite · React Router · DOMPurify · верстка на чистому CSS

## Демо

https://vin-decoder-indol.vercel.app/

## Чому саме це завдання

Перед вибором подивився на дані з обох джерел. У DummyJSON категорія `vehicle` — п'ять товарів з однаковою схемою, все готове до виводу; там основна робота в інтерфейсі. У NHTSA формат VIN зі своїми правилами — фіксована довжина, виключені літери — і два ендпоінти, які треба зв'язати між собою. Мені було ближче саме це: спершу розібратись, що API насправді повертає, і вже потім вирішувати, як це показати.

## Функціонал

**Головна сторінка `/`**

- форма введення VIN з валідацією: непорожнє поле, рівно 17 символів, лише дозволені символи (латиниця без `I`, `O`, `Q`, та цифри)
- історія трьох останніх запитів — зберігається у `localStorage`, переживає перезавантаження сторінки; клік підставляє VIN у форму та повторює розшифровку
- список характеристик автомобіля: виводяться лише змінні із заповненим `Value`
- повідомлення `Message` з відповіді API
- окремий блок з розшифровкою помилок NHTSA, якщо VIN не пройшов перевірку

**Сторінка `/variables`**

- повний список змінних з описами
- пошук за назвою з лічильником знайдених

**Сторінка `/variables/:id`**

- назва, ідентифікатор, тип даних та група змінної
- повний опис з форматуванням

## Особливості реалізації

**Помилки VIN беруться не з `Message`.** Поле `Message` у відповіді NHTSA однакове і для коректного VIN, і для помилкового — завжди «Results returned successfully». Реальна діагностика лежить всередині масиву `Results` у змінних `Error Code` (143) та `Error Text` (191). Застосунок показує `Message` згідно з вимогами, але для попереджень користувача використовує саме ці поля.

**Службові змінні відфільтровані.** Шість змінних (`Suggested VIN`, `Error Code`, `Possible Values`, `Additional Error Text`, `Error Text`, `Vehicle Descriptor`) описують якість розшифровки, а не автомобіль, тому до таблиці характеристик не потрапляють.

**Описи змінних санітизуються.** API повертає описи з HTML-розміткою (`<p>`, `<ul>`, `<li>`). Перед вставкою вони проходять через DOMPurify з білим списком тегів.

**Список змінних кешується** на рівні модуля — обидві сторінки розділу використовують один запит за сесію.

## Локальний запуск

Потрібен Node.js 20+.

```bash
git clone https://github.com/AlexxMushikk/VIN-decoder.git
cd VIN-decoder
npm install
npm run dev
```

Застосунок буде доступний на http://localhost:5173

Збірка для продакшену:

```bash
npm run build
npm run preview
```
